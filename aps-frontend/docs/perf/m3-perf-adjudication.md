## 2. QA-02 的 5–7s：复现结论

**可见窗口下无法复现；只有把浏览器窗口先最小化、再在 5.0–6.8s 后恢复时，FCP 才等于“恢复时刻”。**

| 变量 | FCP（ms，中位数/范围） | DCL（ms） | 结果 |
|---|---|---|---|
| 生产构建 + 回环 + headless=new | **212**（208–264） | 108.3 | 正常，远低于 5s |
| 生产构建 + 回环 + headed 可见窗口 | **276**（228–288） | 115.1 | 正常，headed 本身不是原因 |
| Vite dev server（HEAD，106 个模块，13.8MB 传输） | **392**（364–1200） | 270.1 | 冷启动首轮 1200ms，仍远低于 5s |
| 生产构建 + 10Mbps/40ms | **1712**（1704–1720） | 1538.2 | 符合整改报告 1704ms |
| **窗口先最小化，5.0s 后恢复**（HEAD，4 次） | **5160–5184**（中位 5176） | 114.6–131.8 | **精确复现 QA-02 的 5,140** |
| 窗口先最小化，6.5s 后恢复（HEAD） | **6732** | 123.4 | 对应 QA-02 的 6,176 |
| 窗口先最小化，6.8s 后恢复（HEAD） | **6980** | 119.3 | **精确复现 QA-02 的 6,948** |
| 窗口先最小化，5.0s 后恢复（**当前构建 + gzip**） | **5240** | 130.3 | 与构建无关，证明是测量伪影 |

关键证据：

- 上述最小化跑法在读取指标时，页面仍报告 `visibilityState = "visible"`、`document.hasFocus() = true`，这正是 QA-02 认为“页面保持可见”的原因；但窗口在加载期间被最小化/遮挡时，Chrome 暂停合成帧，FCP 条目要等到窗口恢复、产生首个合成帧才写入。
- 因此出现 QA-02 记录的特征：**FCP 5.1–6.9s，而 DCL 仅 68–261ms**。我们最小化跑法的 DCL 为 114–131ms，量级一致；一旦恢复等待时间落在 5.0/6.5/6.8s，FCP 就同步落在 5.16s/6.73s/6.98s。
- 同配置偶发一次在 2,248ms 记录 FCP（最小化对合成的抑制并非每次立即生效），说明该伪影本身也不可重复为“稳定 5–7s”。
- QA-02 证据目录（`D:\tools\_aps-localdata\m3-qa-02`）只有静态服务器/代理脚本，**没有 FCP 采集脚本**，无法逐行复核其浏览器窗口状态；其引用的 `index-CLunJZq-.js` 也不等于 HEAD 重建立的 `index-C8EXzNa6.js`，说明“复用既有 dist”并非 HEAD 构建。

## 4. 甘特 5000 任务帧率

数据：Mock `5000x50`，**1,667 个订单 / 5,000 个任务**；甘特本体虚拟化后仅渲染 **20 行**（`scrollHeight 56,722px / clientHeight 458px`），但整页 DOM 为 **43,551 个节点**，其中 Element Plus 明细表渲染 **1,837 行**。

工程判定口径：**帧间隔 P95 ≤ 33ms，且无 >100ms 长帧**。

| 场景 | 帧数 | P50 | P95 | P99 | 掉帧率（>33.3ms） | >100ms 长帧 | 判定 |
|---|---:|---:|---:|---:|---:|---:|---|
| 空闲（不滚动） | 180 | 17.6ms | 18.4ms | 18.6ms | 0 | 0 | 基线 |
| 常规滚动（93px/帧） | 1,800 | 17.6ms | **18.3ms** | 34.8ms | **1.2%** | **0** | **达标** |
| 中速滚动（234px/帧） | 720 | 17.6ms | **18.1ms** | 18.6ms | 0.4% | **0** | **达标** |
| 探针同速（468px/帧） | 360 | 17.6ms | **35.0ms** | 35.7ms | 7.8% | **0** | **P95 超 2ms，未达标；但无长帧** |
| 页面自带探针（5 次重载后 120 帧，>25ms 计掉帧） | 120 | — | — | — | 47.5%（>25ms） | — | 37.4 FPS / 26.77ms；瞬时态，无 P95 口径 |

说明：

- 自带探针在 **5 次完整重载后立刻**采样 120 帧、步长 468px/帧（`56,264/120`），把重载后的 GC/重排计入，因此得到 37.4 FPS、47.5%（>25ms）。我们的独立采样在页面稳定后、以相同 468px/帧步长测得 P95 35.0ms；以常规 93–234px/帧滚动则为 18.1–18.3ms。**同一探针在上一构建曾测得 45 FPS，说明该数字随瞬时负载波动，不等于稳态滚动帧率。**
- 三轮 600 帧中出现 6 个 50–90ms 的 longtask，但**没有一帧超过 100ms**；最大帧间隔 87.2ms 出现在一次 GC/布局突发。
- 高度虚拟化使甘特滚动本身接近刷新率；瓶颈只在大步长滚动时出现（每帧跨约 5 行，触发更重的重排/重绘）。

### 首屏 5000 任务的瓶颈归因

| 项 | 实测 |
|---|---|
| Mock 数据加载（load） | **47ms** |
| 分析 + 首屏渲染（render） | **2,660.8ms**（合计 2,707.8ms） |
| 自带探针 5 轮首屏 | avg **3,007ms** / P95 **3,348ms** |
| 整页 DOM / Element Plus 明细表行 | **43,551** 节点 / **1,837** 行（约 17,700 个 `.cell`） |
| CPU 采样（同代码路径，2,590ms，1ms 间隔） | Element Plus 自身约 **0.96s**、GanttTimeline 约 **0.27s**、idle 0.34s、GC 0.05s |

结论：首屏 2.7–3.0s 的瓶颈是**渲染**——Element Plus 明细表一次性渲染 1,837 行（未虚拟化），不是数据取数（Mock 加载仅 47ms），也不是甘特本体（已虚拟化到 20 行）。大步长滚动时的偶发双帧同样来自滚动驱动的重排/重绘，与数据无关。

## 5. 裁定结论

**首屏以“可见窗口”的实测为准：回环 FCP 212–260ms、10Mbps/40ms FCP 740ms（gzip_static on，LCP 832ms），满足 FCP < 2s。QA-02 的 5,140–6,948ms 不可用：它只在“窗口先最小化/被遮挡、窗口恢复时才写入 FCP”的异常跑法下逐值复现（5,160–5,184 / 6,732 / 6,980ms），且同一批运行的 DCL 仅 114–131ms，与其自身“FCP 5–7s、DCL 68–261ms”的矛盾完全同构。**

补充裁定：

- 整改报告的方法与数字可用；HEAD/10Mbps 对照的偏差在 2% 内（HEAD 212 vs 216ms；10Mbps 1712 vs 1704ms）；整改后 740 vs 684ms 为 +8%，可由最终构建增量和同机负载解释。
- QA-02 的 `index-CLunJZq-.js` 无法由 HEAD 重建（HEAD 重建为 `index-C8EXzNa6.js`），其“复用既有构建”的产物来源不可验证，不能作为整改前后 A/B 的基线。
- 甘特 5000 任务：真实滚动速度下达标（P95 18.1–18.3ms，0 个 >100ms 长帧）；按自带探针的 468px/帧步长，P95 35.0ms 超过 33ms 门槛 2ms，但长帧仍为 0。不能笼统写“5000 任务滚动不达标”，也不能写“全程 60fps”。

### 建议如何修订 QA-02 的口径

1. **删除/作废 FCP 行**：将 `FCP 6,176 / 6,948 / 5,140 / 6,948ms（未达标）` 标记为“测量无效（窗口最小化/遮挡导致 FCP 延迟到恢复时刻）”，不要作为验收结论。替换为重测值：回环 212–260ms、10Mbps/40ms 740ms（gzip_static on），目标 <2s **达标**。
2. **采集前校验窗口状态**：断言窗口 `windowState = normal` 且未被遮挡；不要用 `document.visibilityState` 作为可见性判据（最小化时它仍为 `visible`）。headless 优先用 `headless=new`；不要用“先启动再最小化”的自动化窗口。
3. **增加一致性闸门**：同一轮若 `FCP > DCL + 500ms`（或 `FCP - DCL > 1s`），判该轮无效并自动重测；同时记录 `FCP / DCL / LCP / windowState` 四元组。
4. **留档采集脚本**：QA-02 证据目录只有静态服务器与代理脚本，没有 FCP 采集代码；应把浏览器版本、headless 模式、缓存禁用、采样次数一并写入证据。
5. **构建来源可追溯**：不要直接复用来历不明的 `dist`；用 `git archive HEAD` 重建并记录入口 hash（本次 HEAD = `index-C8EXzNa6.js`）。
6. **§8 的“首屏口径拍板”项可关闭**：不是“FCP 还是 DCL 的验收口径之争”，而是原 FCP 测量无效；按修正后的 FCP 口径复测已达标。
7. **补充甘特前端实测**：QA-02 写“5000 任务滚动前端 FPS 无法测量”；本次已测：常规滚动 P95 18.3ms（0 长帧，达标），探针同速 P95 35.0ms（无 >100ms 长帧，边界未达标）。建议在 QA-02 中明确“滚动步长/采样口径”，否则 FPS 数字不可比。

### 仍未覆盖的场景

- QA-02 原始自动化工具本身（无脚本、无窗口状态记录，无法逐行复核）。
