> 报告日期：2026-11-05  
> 调研范围：国内主流 APS／智能排程厂商与“AI 排产”解决方案，重点覆盖悠桦林、杉数科技、兰光、元数科技／MoMaster 系、黑湖科技、鼎捷、用友、金蝶、浪潮、佰思特、摩尔元数、树根互联、海尔卡奥斯。  
> 方法：公开官网、产品页、发布会／新闻稿、公开案例稿、行业媒体；未使用付费研报，未做厂商 demo 与客户访谈。所有“有／部分／无”均以公开资料为限，**没有公开证据不等于厂商没有能力**。  
> 证据分级：**A**＝产品页／产品文档／可核实案例；**B**＝发布会、官网新闻稿、行业媒体（厂商口径）；**C**＝仅营销话术、信息矛盾或无法确认。

## 0. 结论先行

### 0.1 国内竞品已经做到、而我们目前没有的 5 件事

1. **“询单 → 可承诺交期（CTP）→ 插单影响 → 一键下推”的销售—计划闭环**  
   金蝶“小 K 插单模拟”明确基于 CTP 有限产能模型，用自然语言交互模拟插单，自动判断可承诺交期，并支持一键确认与排产下推；鼎捷 APS 明确提供 ATP／CTP 模拟与询单预计交期；杉数“订单测算”直接回答预计交付日期；悠桦林 SCP 5.0 的 AI Agent 提供交期应答。  
   我们目前只有**两档只读 ATP 预估**，缺“产能＋物料＋多级 BOM”耦合的精确 CTP，也缺面向销售询单的工作流与回写。

2. **自然语言直接改约束／改计划的 Agent 执行层**  
   悠桦林 SCP 5.0 已发布 AI Agent（自然语言问答、交期应答、缺料预警、需求预测、运维）；黑湖有独立的“排程 Agent”，让 Agent 理解客户已有任务、资源和表格；杉数 COLORMind 支持“纯自然语言增添／修改目标约束，一键重新建模”；金蝶小 K、浪潮 Mano 也在往“对话式计划”走。  
   我们的 AI 目前是**解读、问答、帮助**，不能把“把这张订单提前两天、这个机台停半天”安全地转成受控 DSL 并执行。

3. **多工厂／多基地的订单路由与协同**  
   金蝶支持多工厂资源智能调度与跨厂订单／工序协同；用友 U9 cloud 是多组织／多工厂 ERP；浪潮 MOM 面向集团多车间；杉数、悠桦林、树根均有跨工厂／多车间计划模块。  
   我们目前是**单工厂、单场景基线**，没有“工厂”维度、跨厂产能池、跨厂日历与订单路由规则。

4. **行业化约束库与实施包**  
   鼎捷 APS 把注塑、五金、电子零组件、汽配、家具等行业的模具、工治具、替代料、连批、人员、机台优先顺序做成行业方案；兰光深耕军工、船舶、高温合金；摩尔元数覆盖电子／PCBA／军工／光学；卡奥斯有服装行业 APS；黑湖主打中小离散。  
   我们有 23 个场景帮助助手和通用约束，但缺**行业约束模板、模具／工装／连批／炉资源等细粒度建模、以及可复制的实施方法论**。

5. **ERP／MES 的原生双向集成与主数据治理**  
   用友、金蝶、鼎捷是 ERP＋MES 同厂，浪潮是 MOM 九模块一体，黑湖、摩尔是 MES／MOM 带排产。它们卖的不只是排产算法，而是“主数据—计划—执行—回写”的闭环。  
   我们目前以 Excel 导入导出＋REST 为主，缺认证连接器、事件驱动、执行回写与主数据对账。

### 0.2 三个市场判断

- **竞争焦点已经从“能不能排出结果”转向“询单能不能承诺、插单影响能不能算清、计划能不能落下去”。** 算法是底座，但客户买单的是闭环。
- **AI 的真实价值集中在三处：降低使用门槛（自然语言）、缩短询单／异常响应、解释与归因。** 没有看到“LLM 直接替代求解器”的可核实案例；真正跑得好的，都是“LLM 负责意图与解释，求解器负责确定性优化”。
- **头部厂商的 AI 落地也大多是“产品发布＋试点”。** 发布会讲“AI 排产”不等于排产 Agent 已在客户产线闭环；本报告对每家的 AI 证据单独标注。

### 0.3 对本项目最重要的一句话

> 先把 **hard score＝0 的求解可信度**和 **CTP 询单承诺闭环**做成产品，再扩展 Agent 与多工厂；否则 AI 只会放大不可信的结果。

### 2.2 AI 能力四层：多数厂商停在 L1／L2

| 层级 | 能力 | 代表厂商（公开证据） | 对本项目的含义 |
|---|---|---|---|
| L1 问答／解释 | 自然语言问系统怎么用、为什么这样排、报表生成 | 悠桦林、鼎捷、浪潮、摩尔、用友、金蝶 | 我们已有“AI 解读＋23 场景帮助”，差距不大 |
| L2 建议／模拟 | 自然语言发起插单模拟、交期应答、缺料预警、方案对比 | 金蝶（插单模拟）、黑湖（急单模拟）、悠桦林（交期应答／缺料预警）、鼎捷（MPS／FAS 助手）、浪潮（AI＋APS） | 我们只有只读 What-if 问答；缺“建议→确认→执行”闭环 |
| L3 执行／改约束 | 自然语言改目标／约束、生成可执行计划、写回求解器 | 杉数（COLORMind 自然语言建模改约束）、黑湖（排程 Agent 理解任务／资源／表格→计划）、金蝶（一键确认下推） | **这是我们最该补的一层**：NL→受控 DSL→dry-run→diff→审批→求解 |

### 2.3 需要警惕的三类营销话术

1. **“AI 排产”＝传统 APS 算法换名字。** 很多厂商的“AI”实质是启发式／遗传算法／规则引擎＋甘特图。算法当然有价值，但它不是 LLM，也不等于自然语言交互。
2. **“大模型排产”＝自然语言问答／报告。** 问一句“为什么延迟”，系统用 LLM 组织答案，不等于 LLM 参与约束求解。真正把自然语言接到求解器的，公开证据集中在杉数 COLORMind、黑湖排程 Agent、金蝶小 K、悠桦林 AI Agent 等少数产品。
3. **“秒级／分钟级排产”＝小规模／预计算／缓存。** 紧约束、大规模、跨资源场景仍取决于求解器时间与算力；厂商案例里的“3 分钟”“20 秒”多为中小规模或特定场景，不能直接外推。

### 2.4 真正值得抄的五个 AI 设计

1. **AI 不求解，只做“意图→结构化参数／约束→调用求解器→解释”**（杉数 COLORMind、金蝶小 K、黑湖排程 Agent）。求解结果必须可复现、可验证；LLM 只负责翻译与编排。
2. **人机协同治理分级**：Agent 建议／人决策、Agent 决策人监督、Agent 自主执行，异常时强制转人工（黑湖明确写出这套治理模型）。国内制造客户更接受“可干预的 AI”。
3. **场景化 Agent，而不是通用聊天机器人**：询单、插单、缺料、履约、报工五个高频场景，比“万能助手”更容易验收。
4. **证据链随结论一起输出**：约束校验通过数、交期风险说明、影响订单清单、瓶颈原因（黑湖、悠桦林、浪潮）。这比“AI 说可以”更能建立信任。
5. **行业知识沉淀**：把工艺路线、换型规则、模具／工装约束、历史排产案例变成模板与知识库（鼎捷、兰光、摩尔）。这是比模型参数更深的护城河。

| 商业化 | 单体＋私有化 Docker；行业模板较弱 | 行业套件＋实施包＋投标资质 | **行业模板／交付体系／信创** |

### 3.2 优先级总表

> 成本为**人日区间**（含开发、测试、联调、文档；不含客户现场实施与差旅）。优先级按“对成交与可信度的影响”排序，不按技术炫技程度排序。

### 3.3 逐项说明（P0 四项）

#### P0-1 求解可信度：跨资源复合移动＋紧题面稳定（15–25 人日）

- **改什么**：在 `solver-timefold` 增加跨资源复合 Move（至少覆盖“换主资源＋相邻工序联动”“成组任务整体移动”“资源锁／时间窗锁下的合法移动”）；建立 hard case 回归集，把当前 -1hard 题面固化为测试；对无解题面输出冲突集合，而不是只返回负分。
- **为什么值得**：客户不会接受“排不出来”或“排出来但违反硬约束”。这是 P0-2／P0-3 的前置；没有它，CTP 承诺和 Agent 改计划都不可信。
- **AI 怎么用**：LLM 不参与 Move 选择；用于把求解失败日志、约束码、冲突任务翻译成“哪条约束卡住了、涉及哪些订单／资源”的归因报告；离线用历史题面做参数／权重调优建议。
- **前置条件**：可复现题面集；Move 级单测；score 一致性校验；基准脚本；契约不变（内部实现为主）。
- **风险**：Move 空间爆炸导致求解变慢；复合 Move 与约束流计分不一致；修复引入回归。建议先做“小范围复合 Move＋开关”，用基准数据验证再默认开启。

#### P0-2 CTP 询单承诺闭环（30–45 人日）

- **改什么**：新增“询单→CTP 模拟→承诺交期→插单影响→确认→回写”的闭环；CTP 计算需耦合产能、物料齐套、多级 BOM、日历、换型；输出“可承诺／需调整／不可承诺”三态与前提条件；保留 ATP 快速档作为粗筛。
- **为什么值得**：这是国内 APS 最容易被销售和计划部门感知的价值点；金蝶、鼎捷、杉数、悠桦林均已产品化。我们只有只读 ATP，销售询单仍靠人。
- **AI 怎么用**：自然语言询单（客户、数量、交期、优先级）；AI 抽取参数、生成模拟假设、解释“为什么不能按期”并给 2–3 个可选方案（加班／换厂／替代料／分批）；AI 只生成建议，最终承诺由规则＋人工确认。
- **前置条件**：MRP pegging；产能模型；订单／询单状态机；C50+ 契约；权限与审计；CTP 求解预算与超时降级。
- **风险**：承诺失准导致违约；主数据质量差导致“算得不准”；销售滥用“可承诺”；精确 CTP 求解耗时。建议先做“只承诺可行窗口，不承诺精确到小时”，并记录承诺依据。

#### P0-3 AI Agent 可写闭环（25–40 人日）

- **改什么**：把 AI What-if 从“问答”升级为“受控执行”：意图识别→槽位抽取→约束 DSL／计划参数草稿→dry-run→diff（影响订单／资源／交期）→人工确认→执行→审计。首批覆盖：插单、锁单／解锁、设备停机、优先级调整。
- **为什么值得**：这是我们与悠桦林 SCP 5.0、黑湖排程 Agent、金蝶小 K 最直接的差距；也是“AI 还能改什么”的核心。客户要的不是聊天，而是“说一句话，系统把事办了，但别乱来”。
- **AI 怎么用**：LLM 负责意图与语言，**不直接写库、不直接求解**；所有写操作必须经过 DSL 校验、dry-run、diff、权限与确认；LLM 失败时回退到表单／现有 AI 解读。
- **前置条件**：C19 DSL 覆盖度；dry-run 已有；幂等；RBAC／审计；LLM 网关与降级；前端确认与 diff 展示；操作回滚。
- **风险**：幻觉生成非法约束；越权写操作；审计缺失；LLM 不可用时的体验断崖。建议先做“只生成草稿，不自动执行”，跑 20–30 个真实场景评测后再开写。

#### P0-4 可解释性 2.0（15–25 人日）

- **改什么**：在现有约束归因上补三类输出：(a) 冲突归因（哪条硬约束／资源／时间窗导致不可行）；(b) 反事实（延哪张单、换哪台机、加哪个班能让这张单提前）；(c) 最小改动建议（对当前计划改动最少且能达成交期的方案）。
- **为什么值得**：客户不只需要“为什么”，更需要“怎么办”；这是 AI 最容易做出差异化、且不依赖求解器升级的地方。
- **AI 怎么用**：LLM 把结构化归因翻译成业务语言；生成 2–3 个反事实方案并调用求解器验证；明确标注“已验证／未验证”，避免过度承诺。
- **前置条件**：约束码稳定；归因重放与求解口径一致；反事实求解预算控制；解释模板。
- **风险**：归因口径与求解器分叉；反事实求解耗时；解释过度承诺。建议把“解释”和“验证”分开：先解释，再按需验证。

### 3.5 建议的 90 天落地路线

| 阶段 | 重点 | 交付物 | 门槛（建议，需产品确认） |
|---|---|---|---|
| 第 1–4 周 | 求解可信度 | hard case 集、复合 Move、失败归因报告 | 20 个 hard case 全部 hard score＝0 或明确冲突集合；无回归 |

| 并行 | 商业验证 | 1–2 家种子客户试点；行业模板初版 | 试点客户愿意用“询单＋插单”两个场景；形成可复述的 ROI 故事 |

### 3.6 不建议做的事

- **不要自研 MIP／CP 求解器。** 杉数 COPT 是十年积累；我们应把精力放在建模、交互、行业约束与交付，求解继续用 Timefold，必要时补 OR-Tools CP-SAT。
- **不要让 LLM 直接求解或直接写库。** LLM 负责任务理解、DSL 草稿、解释与编排；求解与写操作必须确定性、可验证、可审计。
- **不要盲目升级 Timefold 企业版。** 先做基准测试，确认多线程／分区搜索在真实题面上的收益，再谈 License。
- **不要一开始做全栈 Agent 平台。** 先做询单、插单、缺料三个高频场景；L4 编排等 P0-3 稳定后再做。
- **不要承诺“AI 自动排产、无需人工”。** 国内制造客户要的是“可干预、可解释、可追责”的 AI；人机协同比无人化更好卖。

## 4. 方法与来源

### 4.1 方法与局限

- 仅使用公开网络资料，未使用付费研报、未做厂商 demo、未访谈客户；因此“能力有无”以公开产品页为准，“落地效果”以公开案例为准。

## 5. 附：报告口径速记

- **“有”** 不等于“强”：矩阵看的是能力存在性，不是规模、性能、成功率。
- **“AI 有真实落地”** 不等于“排产 AI 有真实落地”：本报告把“工艺 AI”“MOM 问答 Agent”“排产 Agent”分开判断。
- **“厂商案例”** 不等于“第三方验证”：黑湖、鼎捷、金蝶、浪潮的客户数字均为厂商口径；需要尽调时建议要客户联系人、验收报告或现场演示。
- **对我们的建议顺序**：先 P0-1（可信求解）→ P0-2（CTP 闭环）→ P0-3（Agent 可写）→ P0-4（可解释 2.0）→ 再谈 P1 多工厂／行业包／连接器。
